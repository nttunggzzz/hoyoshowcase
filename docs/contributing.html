HANDBOOK / 02

Làm việc cùng nhauHai người, một nhánh main ổn định.

Mục tiêu là mỗi PR nhỏ, dễ đọc và có bằng chứng kiểm tra. Không cần áp dụng quy trình nặng để cùng sửa một project nhỏ.

Ngày đầu của người cùng làm

  1. Clone repo, chạy npm ci và npm run check.
  2. Đọc README HTML, kiến trúc và hợp đồng dữ liệu.
  3. Dùng npm run demo để xem flow; dùng tài khoản của chính mình khi cần kiểm tra dữ liệu thật.
  4. Tạo nhánh và thống nhất khu vực source sẽ sửa. Không gửi credential qua issue, PR hoặc chat.

Chia việc để giảm conflict

Luồng công việc File chính Điểm cần báo nhau
Server / collector src/server, test collector/auth/server Schema, trạng thái mới, endpoint local, field model.
UI / showcase public/js/showcase.js, HTML, CSS ID DOM mà collection-controller hoặc preview đang dùng.
Preview / canvas public/js/preview, src/shared/preview-config.mjs Config mới, version localStorage, kích thước PNG và field nhân vật.

Đừng vừa đổi tên hàng loạt vừa sửa hành vi trong một PR. Khi phải sửa cùng file, merge PR nhỏ đầu tiên rồi rebase nhánh còn lại. Giữ test giả lập trong cùng PR với thay đổi logic.

Nhánh và PR

git switch main
git pull --ff-only
git switch -c feat/preview-layout

# sửa source, rồi kiểm tra
npm run check
git add public src tests docs
git commit -m "feat: add preview layout option"
git push -u origin feat/preview-layout

Mở PR vào main, mô tả trigger, kết quả trước/sau và cách kiểm tra. Với UI, kèm ảnh desktop/mobile hoặc PNG; ẩn UID nếu không muốn chia sẻ. Người còn lại review rồi mới merge. CI chạy trên Linux/Windows, Node 22/24, không dùng tài khoản thật. Project chỉ thêm workflow kiểm tra, chưa tự đặt branch protection.

Một thay đổi sẵn sàng review khi nào?

  • npm run check đạt; không chỉ chạy node --check.
  • Test bao phủ hành vi có ý nghĩa: dữ liệu thiếu, limit, role isolation, lỗi hoặc phân trang nếu bị ảnh hưởng.
  • UI kiểm tra cả khung hẹp và desktop, sáng/tối nếu đổi màu; PNG được tải và xem thật.
  • Tài liệu setup/API/schema được cập nhật khi hành vi đó đổi.
  • git diff --check sạch và danh sách file staged không chứa dữ liệu riêng.

Quy ước source

Dùng ES modules, tên file kebab-case, 2 dấu cách, LF và Prettier. Giữ runtime không dependency trừ khi đã thống nhất nhu cầu cụ thể. Đặt comment ở lý do hoặc ràng buộc giao thức; tránh diễn giải lại từng dòng code.

Form không trực tiếp vẽ canvas; renderer không tự sửa localStorage. Không copy công thức layout vào nhiều file. Field mới từ API nên giữ ở raw snapshot, nhưng chỉ đưa vào view model khi UI cần. Tên trạng thái/schema là hợp đồng; đổi chúng cần bàn với người phụ trách frontend.

Cách kiểm tra theo thay đổi

Thay đổi Kiểm tra nên có
Auth/transport Fixture CAPTCHA/OTP, expired/rate limit, không lộ cookie; không retry đăng nhập tự động.
Collector Batch, pagination, dữ liệu thiếu, cancel/fatal và quyền sở hữu role.
Preview Limit, tổng số, kích thước, config cũ, field thiếu; kiểm tra PNG thực tế trong browser.
Route/lưu file Asset MIME, dữ liệu không bị phục vụ, lỗi file và ghi nguyên tử.
HTML docs npm run check:docs, mở trang và thử link; chỉnh print/mobile nếu đổi layout.
