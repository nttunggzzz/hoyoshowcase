Phiên & dữ liệu riêngBiết thứ gì nằm ở đâu.

Thiết kế hiện tại dành cho app local. GitHub chứa source và fixture; thông tin đăng nhập và dữ liệu tài khoản thật không thuộc repo.

Bản đồ lưu trữ

Dữ liệu Ở đâu Vòng đời
Password / token / cookie / challenge Context server RAM; password mã hóa cho request login. Reset hoặc TTL phiên 20 phút; không xuất trong snapshot/audit.
Cookie phiên local Trình duyệt, HttpOnly, SameSite=Strict, riêng port. Tối đa 20 phút; không phải cookie upstream HoYoLAB.
Device ID web localStorage, UUID không bí mật. Giữ ổn định giữa các lần đăng nhập.
Theme / nhân vật nổi bật / config preview localStorage, theo UID/server ở phần tương ứng. Giữ trên trình duyệt, không đi vào Git.
Snapshot game data/battle-chronicle-latest.json. Giữ để mở lại nhanh; lượt complete mới thay bản trước.
Ảnh PNG / JSON do tải xuống Thư mục Downloads do trình duyệt quản lý. Người dùng tự quản lý và quyết định chia sẻ.

Nút Kết thúc phiên và xóa RAM không xóa dữ liệu game đã lưu. Muốn xóa hồ sơ local, dừng app rồi tự xóa file trong data. Muốn giữ nhiều tài khoản, backup file riêng trước khi đồng bộ role khác; app hiện lưu một bản hoàn tất mới nhất.

Ranh giới mạng

  • Server bind 127.0.0.1, kiểm tra Host chính xác. POST cần Origin và CSRF đúng phiên.
  • Transport dùng registry endpoint cố định; endpoint collector chỉ đọc dữ liệu game.
  • CAPTCHA chạy trong iframe sandbox và người dùng tự hoàn tất. Không tự gửi OTP.
  • Proxy ảnh chỉ nhận CDN raster đã cho phép, chặn redirect và URL lạ, giới hạn kích thước/cache.
  • Cookie upstream không gửi vào luồng tải ảnh; lỗi/audit không ghi URL có authkey, request body hoặc credential.

Đưa app lên một host dùng chung cần một thiết kế xác thực/lưu trữ khác. Không chỉ đổi bind sang 0.0.0.0 hoặc mở tunnel cho server hiện tại.

Những gì được commit

Source, docs HTML, test giả lập, asset công khai có attribution và lockfile. data/.gitkeep là file duy nhất trong thư mục data được theo dõi. Tệp .env, log, zip, vault, capture và snapshot thật bị bỏ qua. npm run check:private còn kiểm tra file bị force-add và JSON có schema snapshot; đây là guard theo loại file, không phải bộ nhận diện mọi dạng secret.

Trước khi đính kèm ảnh vào PR, kiểm tra UID/tên nhân vật/chi tiết tài khoản có phù hợp để chia sẻ không. Khi báo lỗi chỉ cần bước tái hiện, operation, retcode và trạng thái; dùng fixture hoặc bản đã ẩn dữ liệu để tái hiện.

Nếu vô tình commit credential

Dừng chia sẻ, vô hiệu hóa/đăng xuất credential liên quan tại nhà cung cấp và báo người cùng làm. Xóa ở commit mới không tự xóa khỏi lịch sử Git. Chỉ xử lý lịch sử hoặc force-push sau khi thống nhất để người còn lại không tiếp tục phát tán commit cũ. Không dán credential đó vào issue để minh họa.
